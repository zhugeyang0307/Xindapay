📖 信达支付 · V2 新版文档RSA 签名

RSA 签名（SHA256WithRSA）· 更安全的接口鉴权 · 推荐新商户使用

协议规则

请求数据格式application/x-www-form-urlencoded
返回数据格式JSON
字符编码UTF-8
签名算法RSA (SHA256WithRSA)，商户 keytype=1 时强制使用
本页为 V2 文档，使用 RSA 签名。若你使用的是 MD5 签名，请切换到 V1 文档。

签名算法

通用步骤

1、取所有请求参数（不含数组、文件等），剔除 sign、sign_type 和空值。

2、按参数名 ASCII 码从小到大排序（a→z）。

3、拼接成 a=b&c=d&e=f 格式（不要 URL 编码）。

4、得到待签名字符串 signStr。

RSA 签名（V2）

sign = base64_encode( openssl_sign( signStr, 商户私钥, SHA256WithRSA ) )

前置步骤：先在商户后台 → 个人资料 → API信息 生成「商户 RSA 密钥对」，把 商户私钥 保存到你的服务器代码中（不要泄露）。

平台公钥用于验证接口返回数据的签名（回调通知的验签）。

V2 接口请求必须携带 timestamp（10 位秒级整数），且与服务器时间相差 ≤ 300 秒，否则会返回「时间戳字段不正确」。

页面跳转支付

用于前台直接发起支付，支持 GET 或 POST。

https://pay.yunzexinda.com/submit.php

请求参数

字段名变量名必填类型示例值说明
商户IDpid是Int1001商户后台编号
支付方式type否Stringalipay不传则跳收银台
商户订单号out_trade_no是String20261016001只能含 a-zA-Z0-9.\_-|
异步通知地址notify_url是Stringhttp://你的域名/notify.php必须是完整 URL
跳转通知地址return_url是Stringhttp://你的域名/return.php支付完成后浏览器跳转
商品名称name是StringVIP会员超过 127 字节自动截断
商品金额money是String1.00单位：元，最多 2 位小数
业务扩展参数param否String支付后原样返回
指定通道IDchannel_id否Int不传由系统自动分配
身份证号cert_no否String部分业务需要
真实姓名cert_name否String部分业务需要
最低年龄min_age否Int部分业务需要
签名字符串sign是String见「签名算法」
签名类型sign_type是StringRSA与商户 keytype 匹配
⚠️ 注意：此接口 不支持 clientip 和 device 参数，系统自动识别 IP 和设备。不要传，传了也不会被使用。

返回结果

{
  "code": 1,
  "msg": "",
  "trade_no": "20261016123456789",
  "out_trade_no": "20261016001",
  "payurl": "https://pay.yunzexinda.com/paypage/mapay.php?trade_no=20261016123456789"
}

拿到 payurl 后 302 跳转或 window.location 跳转即可让用户付款。

返回结果（JSON）

{
  "code": 0,
  "trade_no": "20261016123456789",
  "pay_type": "jump",           // jump | qrcode | html
  "pay_info": "https://..."
}
1. code=0 表示成功。
2. code=-3 签名错误；code=-4 参数缺失。
3. clientip 必须是合法 IP。

支付结果通知（异步）

订单支付成功后，平台会 GET 请求你提交的 notify_url。

收到后请返回纯文本 success（无引号无空格），否则平台会重试多次。

字段名变量名类型说明
商户IDpidInt
平台订单号trade_noString信达支付系统内订单号
商户订单号out_trade_noString发起支付时的订单号
支付方式typeString如 alipay
商品名称nameString
商品金额moneyString
交易状态trade_statusString只有 TRADE_SUCCESS 是成功
业务扩展参数paramString原样返回
签名字符串signString使用平台公钥验证（RSA）
签名类型sign_typeStringRSA
建议处理逻辑：验签通过 → 检查 trade_status 是否为 TRADE_SUCCESS → 更新你的订单 → 输出 success
