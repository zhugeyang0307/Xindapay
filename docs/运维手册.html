四、故障排查

4.1 用户下单 404 / 500

  1. 看 /www/wwwlogs/pay.yunzexinda.com.error.log 末尾
  2. 检查 pay_order 有没有创建成功
  3. 检查 plugins/mapay/mapay_plugin.php 语法（php -l）
  4. 检查用户有没有可用收款码：SELECT * FROM pay_qrcode WHERE uid=xxx AND status=1

4.2 订单不完成（APK 上报了但订单还是 status=0）

  1. 看 pay_listen_log 最新记录，找 match_status
    • =1 → 匹配上了，看 Order::complete 报什么错
    • NULL → 没匹配（时间/金额不对）
  2. 检查 APK token 对应 pay_license.uid 跟订单 uid 是否一致
  3. 检查订单是否超 10 分钟窗口
  4. 看 Order.php 里码商余额是否充足

4.3 邮件没收到

  1. 看 telegram/hook.log 末尾，找 pushUid 和邮件分支
  2. 看 pay_mail_pending 有没有记录
  3. 检查 pay_user.sub_push_email 和 sub_push_status
  4. 检查 pay_qrcode.mail_to 和 mail_enabled
  5. 检查 pay_user_botconfig.mail_enabled/mail_to
  6. SMTP 配置错误 → 看 error.log

4.4 推送 hook 没触发

  1. 看 telegram/hook.log 最后修改时间，是否最新
  2. 检查 includes/lib/Order.php 里 hook 启动段（PHP_BINARY 问题）
  3. 手动跑：php telegram/hook_order_paid.php TRADE_NO

4.5 下级看不到自己收款码

  1. 检查 pay_qrcode.uid = 下级 uid
  2. 检查 status=1
  3. 检查 min_amount/max_amount 是否覆盖订单金额

九、智能路由运维

涉及文件：user/qrcode_route.php + pay_qrcode_route 表 + pay_qrcode.weight 字段 + plugins/mapay/mapay_plugin.php 的 pickByRoute/pickByWeight。

9.1 数据结构

表/字段作用
pay_qrcode_route路由规则（uid 隔离，每商户独立）
pay_qrcode.weight码权重（默认 100，越大越容易被选中）
pay_qrcode.bind_province上传时根据 bind_ip 自动解析的省份

9.2 规则类型

  • province：按客户省份匹配（match_value = {"provinces":["广东","江苏"]}）
  • weight：无条件命中，按 qrcode_ids 里的码加权随机
  • all：兜底（语义是"其他都没命中时用"）

9.3 匹配优先级

路由规则（priority 越小越先匹配）
  ↓ 命中
从规则里的候选码池按 weight 加权随机
  ↓ 无规则命中
客户 IP 省份 优先匹配 region_province / bind_province
  ↓
多个候选按 weight 随机
  ↓
都没命中 → use_count 最少
  ↓
再没有 → 原逻辑（本人码优先 → 下级 BFS 最多 3 层）

9.4 规则不生效排查

  1. 检查 pay_qrcode_route.status=1（是否启用）
  2. 检查 priority 排序（小的优先）
  3. 检查匹配类型（province 时 match_value 必须有 provinces 数组）
  4. 检查候选码是否 status=1 / 金额区间 / 日限额
  5. 到「功能测试中心 → 收款码选择测试」跑一遍看实际结果

9.5 权重设置

-- 查权重异常
SELECT id, uid, remark, weight FROM pay_qrcode WHERE weight > 1000 OR weight = 0;

-- 修改
UPDATE pay_qrcode SET weight=60 WHERE id=119;
UPDATE pay_qrcode SET weight=40 WHERE id=120;

十、IP 检测与地区匹配

10.1 数据源

  • 本地库：route/data/ip2region.xdb（XdbSearcher 读取）
  • 查询类：route/lib/IpLocation.php
  • 工具页：user/myip.php（?act=query&ip=me 返回当前访问 IP）

10.2 数据库字段

字段说明
pay_qrcode.bind_ip上传码时绑定的 IP
pay_qrcode.bind_province该 IP 解析出的省份
pay_qrcode.bind_city该 IP 解析出的城市
pay_qrcode.region_province手填的归属省份（优先于此字段）

10.3 更新 IP 库

# 下载最新
wget -O /tmp/ip2region.xdb https://github.com/lionsoul2014/ip2region/raw/master/data/ip2region.xdb
# 覆盖
cp /tmp/ip2region.xdb /www/wwwroot/pay.yunzexinda.com/route/data/ip2region.xdb
chown www:www /www/wwwroot/pay.yunzexinda.com/route/data/ip2region.xdb

10.4 识别错误处理

  • VPN / 代理 IP → 会显示代理所在地
  • 4G/5G 手机 → 可能显示运营商出口省份
  • CDN → 显示 CDN 机房 IP
  • 处理：手动填 region_province 覆盖自动识别

十三、收款码监控与清理

13.1 数量说明

已取消数量上限（改自 2026-10-17）。但需定期清理失效码。

13.2 定期巡检 SQL

-- 长期未用的码
SELECT id, uid, channel, remark, use_count, last_used
FROM pay_qrcode
WHERE status=0 OR (last_used < UNIX_TIMESTAMP(DATE_SUB(NOW(), INTERVAL 90 DAY)))
ORDER BY uid;

-- 权重异常的码
SELECT id, uid, remark, weight FROM pay_qrcode WHERE weight > 1000 OR weight = 0;

-- 绑定 IP 但省份解析失败的码
SELECT id, uid, bind_ip, bind_province FROM pay_qrcode
WHERE bind_ip IS NOT NULL AND (bind_province IS NULL OR bind_province='');

13.3 清理建议

  • 每月检查一次已停用/未用 90 天的码
  • 通知商户主动清理
  • 超过 1 年未用的码 → 备份后删除
  • 系统管理员也可在 admin 后台强制下线失效码

十四、快速故障恢复

14.1 收款码选不到

  1. 功能测试中心 → 收款码选择测试
  2. 看是"未匹配到"还是"匹配到错误的码"
  3. 未匹配 → 查 pay_qrcode 的 status / 金额区间 / 日限额
  4. 匹配错 → 查 pay_qrcode_route 的 priority 与 match_type

14.2 邮件不到账

  1. tail -50 telegram/hook.log 看最近记录
  2. 查 pay_mail_pending 最新 5 条
  3. 功能测试中心 → 邮件推送测试
  4. 检查商户的 sub_push_email / SMTP 配置

14.3 IP 归属地识别错误

  1. 功能测试中心 → IP 归属地测试
  2. 点 ip138 外链人工核对
  3. 必要时让商户手动选 region_province

14.4 下级推送失败

  1. 查 pay_user.sub_push_status（0=待审 1=通过 2=拒）
  2. 上级后台 → 下级推送审批 → 🧪 测推送
  3. 下级推送资料页 → 检查邮箱/SMTP 是否正确

14.5 智能路由规则不生效

  1. 查规则 status=1
  2. 查 priority 排序
  3. 用功能测试中心模拟选码
  4. 检查候选码的 weight 是否合理

14.6 回调失败（notify_url 返回非 200）

  1. 订单详情看"回调"列状态
  2. 功能测试中心 → 回调测试（发一笔测试 POST）
  3. 查客户服务器的 Nginx access log
  4. 确认对方 URL 是否公网可达
