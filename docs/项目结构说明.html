🏗 项目结构说明

生成：2026-10-17 | 用途：开发/运维/接手必读

📌 项目定位

SaaS 支付系统服务商，不参与收款。商户注册 → 实名认证 → 审核通过 → 使用系统。

  • 服务方式：开户即用，不抽成，不按笔收费，收多少拿多少
  • 适用范围：商户/码商/下级按需使用，不另收月费
  • 支持 3 级子商户（码商代收模式）

十一、核心业务链路

链路 1：收单

商户 API → submit.php → Channel.php 选通道
       → mapay_plugin::pickWithChildren（找码：本人优先→下级）
       → 写 pay_order.ext = {qrcode_id, qrcode_uid}
       → 跳 paypage/mapay.php → 展示收款码

链路 2：APK 上报 → 订单完成

APK 监听微信/支付宝到账 → POST paypage/notify_listen.php
       → 验签 → 匹配 order（uid + 金额 + 10min 内）
       → 码 owner ≠ 订单 uid？→ 扣码 owner 余额
       → 上级按 rate 分成 → 加上级余额
       → Order::complete → 回调商户
       → 触发 telegram/hook_order_paid.php（异步）

链路 3：推送

hook_order_paid.php:
  pushUid = 码 owner（10002）
  ├─ 码级邮件配置？→ 用码级
  ├─ sub_push_email？→ 用下级推送资料
  ├─ pay_user_botconfig？→ 商户邮件
  └─ TG 推送

链路 4：邮件确认

邮件点「确认到账」→ mail_confirm.php?token=xx&action=ok
  → MailOrder::verify(token)
  → Order::complete(trade_no)
  → do_notify(notify_url)

十二、注意事项

  1. 绝不传 config.php 和 telegram/config.php
  2. 上传时不要覆盖这两个文件
  3. _dev_login.php 和 _test*.php 上线前必删
  4. 数据库备份优先级：pay_user > pay_order > pay_record
