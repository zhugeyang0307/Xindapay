👨‍💼 商户操作手册

面向一级/二级/三级商户完整操作流程

一、注册与认证

1.1 注册

  1. 访问 https://pay.yunzexinda.com/user/reg.php
  2. 填写账号、密码、邮箱（邮箱用于找回密码 + 收订单通知）
  3. 提交后自动开通 2 天试用

1.2 实名认证

  1. 登录后台 → 我的账号 → 实名认证
  2. 上传证件 + 填写真实信息
  3. 等待平台审核（1-24 小时）
  4. 审核通过后才能使用收单功能

二、系统服务续费

2.1 查看服务期

后台 → 💎 系统服务 → 显示到期时间 + APK 额度

2.2 服务说明

  1. 开户即用：不抽成、不按笔收费，收多少拿多少。
  2. 设备按实际使用配置：APK 与收款码按需使用。
  3. 服务状态变更后，收单、APK 上报、推送将按后台配置生效。
注意：服务期到期后，收单、APK 上报、推送全部停止，需重新更新服务状态后恢复。

三、收款码管理

3.1 上传收款码

  1. 后台 → 收款工具 → 收款码管理 → 新增
  2. 上传微信/支付宝收款码图片 或 粘贴收款链接
  3. 填写备注、渠道类型（支付宝个人/商户/聚合等）
  4. 设置限额：单笔最小/最大金额（0=不限）
  5. 设置日限额：笔数、总金额
  6. 可选：设置地区（只收本省）

3.2 开关收款码

列表页每行右侧有「启用/停用」按钮，一键切换。

3.3 渠道类型说明

渠道说明
alipay_personal支付宝个人码
alipay_biz支付宝商家码
wechat_personal微信个人码
wechat_biz微信商家码
aggregate_both聚合码（支付宝+微信）

四、APK 激活码

4.1 领取

  1. 先实名认证通过
  2. 后台 → 收款工具 → 我的激活码 → 领取
  3. 每次领 1 个，最多 3 个（可加钱买额度）

4.2 安装 APK

  1. 下载 APK 到监听手机（安卓）
  2. 打开 APP → 输入激活码 → 激活
  3. 授权：通知监听 + 悬浮窗 + 自启
  4. 保持后台常驻，勿被系统杀

五、订单管理

5.1 我的订单

后台 → 经营数据 → 订单记录。显示：订单号、金额、状态、支付方式。

5.2 下级订单

后台 → 下级商户 → 下级订单。可选「含下级 / 只看我的」切换。

5.3 订单完成流程

客户下单 → 系统分配收款码 → 展示给客户
         → 客户扫码付款 → APK 监听到账
         → 系统自动完成订单 → 触发通知
         → 码 owner 收到邮件/TG 推送
         → 点击「确认到账」→ 完成回调

六、推送配置

6.1 邮件推送

🆕 新版入口：后台左侧「📤 推送中心」→ 邮件推送（user/mail_push.php）
  1. 后台 → 推送 → 我的推送资料
  2. 填邮箱（收订单通知）
  3. 填 SMTP 服务器（可选，用自己邮箱发件）
  4. 提交 → 上级审批 → 通过后生效

6.2 TG 推送

🆕 新版入口：后台左侧「📤 推送中心」→ 机器人管理（user/telegram.php）
  1. 找 @userinfobot 拿 Chat ID
  2. 后台 → 机器人管理 → 绑定 Bot
  3. 填 Chat ID

6.3 推送渠道自主选择（新版）

⚠️ 重要变更：订单推送渠道不再由系统「邮件优先、TG 兜底」自动决定，改为 商户自行选择。

入口：后台 → 📤 推送中心 → 机器人管理 → 页面顶部「订单推送渠道」

选项含义说明
不推送关闭订单通知订单到账时不主动推送，需进后台手动确认
仅邮件只发邮件需先在「📧 邮件推送」配置好收件邮箱
仅 TG只推 TG需先在「机器人管理」绑定 TG 或配置自建机器人
邮件 + TG双保险两个渠道都推送，推荐无人值守场景
⚠️ 标准商户组（gid=4）强制自建
• 选「仅邮件」或「邮件 + TG」→ 必须在「邮件推送」填自己的 SMTP 服务器，平台不会用默认邮箱代发
• 选「仅 TG」或「邮件 + TG」→ 必须在「机器人管理」配置自己的 Bot Token，平台主机器人不会代发
• 配置不全时保存会提示错误，无法生效

七、下级商户管理

🌲 树形层级展示：下级商户列表已改为树形排列——二级商户会自动缩进显示在你的下方并带 └ 符号，三级再缩进一层，一眼看清「谁是谁的下级」。平台管理员后台的商户总列表也是同样的树形结构，按层级从高到低排列。
📌 默认分组：新创建的下级自动归属于「标准商户组」，无需手动配置即可收款。

7.1 创建与下发下级

  1. 后台 → 下级商户 → 创建下级
  2. 填账号、密码、层级（2 或 3）并提交。
  3. 提交成功后，系统会弹窗显示账号和密码。请到「下级商户管理」列表，点击对应的【📋 复制登录】按钮，系统会自动生成包含专属登录链接、账号和密码的完整信息。
  4. 直接将该信息粘贴发送给下级即可，下级必须通过此专属链接才能正常登录（最多 3 级：A→B→C）。

7.2 编辑下级

字段说明
分润比例（rate）下级收款时上级拿的 %（0-50）
收款权限（pay）关闭后下级无法收款
增加余额从上级余额划给下级
扣减余额从下级余额划给上级

7.3 审批下级推送资料

下级填的推送资料 → 上级在「下级推送审批」通过/拒绝。

八、账单核对

8.1 下级上传账单

  1. 下级登录 → 对账单管理 → 上传
  2. 支持 CSV/TXT/ZIP/XLSX
  3. 微信账单加密 ZIP 需填密码（在微信「服务通知」里）
  4. 系统自动解析入库

8.2 上级核对下级账单

  1. 后台 → 下级商户 → 下级账单核对
  2. 看到下级所有批次，点「明细」看每条
  3. 点「对账」→ 系统订单 vs 账单自动匹配
  4. 核对完 → 点「🗑 核对完删除」（软删）
  5. 切到「已删除」Tab 可恢复
对账原理：按「金额一致 + 时间差 < 10 分钟」匹配。
- ✅ 匹配 = 系统订单和账单都有
- ⚠️ 系统独有 = 系统有但账单没记录（可能漏单）
- ❌ 账单独有 = 账单有但系统没订单（可能用户直接扫码）

九、对账中心

十、邮件营销与追踪系统

📌 功能定位

商户向自己的客户群发营销邮件（促销、通知、召回等），并追踪每封邮件的打开 / 点击 / 落地页 / 转化数据。

  • 发件人 = 你自己的邮箱（用你的 SMTP）
  • 追踪 = 内置 1×1 像素 + 链接重写 + 落地页 SDK

10.3 创建邮件活动

后台 → 邮件营销 → 点「➕ 新建活动」

填写内容

字段说明
活动名 *仅自己可见，方便管理（如「双十一促销」）
邮件主题 *收件人看到的标题
发件人显示名选填（如「XX 商城」），默认显示你的邮箱
邮件正文 *HTML 编辑器（支持所有 HTML 标签）
收件人 *手动输入 / 从订单买家邮箱勾选

正文来源 3 种方式

  1. 直接编辑：在文本框里写 HTML
  2. 从模板导入：选已有模板一键填入
  3. 导入本地 HTML：点「导入 HTML」选本地 .html 文件（UTF-8）

收件人来源 2 种方式

  1. 手动粘贴：每行一个，或用逗号/分号/空格分隔
    系统自动去重 + 格式校验，无效邮箱会红字提示
  2. 从订单拉取：点「加载历史买家邮箱」→ 勾选（支持全选）
    取自己名下所有已支付订单的买家邮箱

邮箱验证规则（保存时会强制校验）：

  • 格式必须合法（正则验证）
  • 域名不能是测试/保留域名（example.com、test.com、mailinator 等）
  • 域名必须有 MX 或 A 记录（checkdnsrr 检查）
  • 不符合的会显示具体原因，需修正后重新提交

10.8 落地页追踪 SDK（高级）

用途：把追踪装到你自己的落地页上，统计访问和转化。

接入步骤

  1. 后台 → 邮件营销 → 「追踪接入」（track_sdk.php）页面有完整说明
  2. 把 SDK 脚本加到落地页 <head> 里：
    <script src="https://pay.yunzexinda.com/mail_track/track/sdk.js"></script>
  3. 邮件里的链接会自动加 mt_rid=xxx 参数，SDK 检测到就自动追踪

上报转化事件

在落地页支付成功/下单成功时调：

mtTrack.event('purchase', {amount: 199, order: 'ORD123'});

后台就能在「追踪明细 → 仅转化」看到，显示金额和订单号。

原理：

  1. 邮件里的 <a href> 全部被重写成 click.php?t=token&url=base64
  2. 用户点击 → click.php 记录事件 → 302 跳到真实 URL 并加 ?mt_rid=token
  3. 落地页 SDK 读 mt_rid，自动上报 landing 事件
  4. 页面里调 mtTrack.event() 上报自定义转化

10.9 常见问题

Q1：点「开始发送」没反应？

  • 检查 SMTP 是否配好（mail_push.php）
  • 检查有没有未发送的收件人（顶部「未发送」数字）
  • F12 Console 看是否有 JS 错误

Q2：发送失败率高？

  • 看收件人列表的失败原因（鼠标悬停在红色「失败」标签）
  • 常见原因：邮箱不存在 / SMTP 限流 / 被当垃圾邮件
  • 换「慢速稳发」模式再试

Q3：打开率是 0？

  • 很多邮箱默认屏蔽远程图片（追踪像素就是图片）
  • 用户必须「显示图片」才能记录打开
  • 所以真实打开率通常比统计值高

Q4：能发多少封？

  • 系统限制：单批最多 100，每封间隔 ≥ 0.3 秒
  • 实际上限取决于你的 SMTP 服务商（Gmail 免费版 500/天，企业版 2000/天）
  • QQ 邮箱每天 50 封左右

Q5：收件人会看到追踪吗？

  • 打开追踪：看不见（1×1 透明像素）
  • 链接追踪：看不见跳转（302 秒跳）
  • 落地页 URL 会多一个 ?mt_rid=xxx 参数（无感）

十一、常见问题

Q1：下单后客户看不到收款码？

  • 检查商户有没有启用的收款码（status=1）
  • 检查收款码限额是否覆盖订单金额
  • 检查服务期是否有效

Q2：订单已经付款但系统没完成？

  • APK 是否在线（查看手机 APP 状态）
  • 金额和时间是否在 10 分钟内匹配
  • 看码 owner 余额是否不足

Q3：邮件没收到？

  • 检查推送资料是否通过审批
  • SMTP 配置是否正确
  • 看垃圾邮件箱

Q4：下级收不到推送？

  • 下级推送资料是否已填 + 上级审批通过
  • 订单 pushUid 是否是下级 uid
