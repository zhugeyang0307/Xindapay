## 👨‍💼 商户操作手册

面向一级/二级/三级商户完整操作流程

## 一、注册与认证

### 1.1 注册

- 访问 https://pay.yunzexinda.com/user/reg.php

- 填写账号、密码、邮箱（邮箱用于找回密码 + 收订单通知）

- 提交后自动开通 2 天试用

### 1.2 实名认证

- 登录后台 → 我的账号 → 实名认证

- 上传证件 + 填写真实信息

- 等待平台审核（1-24 小时）

- 审核通过后才能使用收单功能

## 二、系统服务续费

### 2.1 查看服务期

后台 → 💎 系统服务 → 显示到期时间 + APK 额度

### 2.2 账户与服务

- 开户即用：不抽成、不按笔收费，收多少拿多少。

- 设备按需使用：APK 与收款码按实际需用配置。

- 服务到期后，收单、APK 上报、推送将全部停止，需重新续期/更新服务状态。

### 6.1 邮件推送

### 6.2 TG 推送

> 🆕 **新版入口**：后台左侧「📤 推送中心」→ 机器人管理（页面路径 `user/telegram.php`）

- 找 @userinfobot 拿 Chat ID

### 6.3 推送渠道自主选择（新版）

> ⚠️ **重要变更**：订单推送渠道不再由系统「邮件优先、TG 兜底」自动决定，改为**商户自行选择**。

**入口**：后台 → 📤 推送中心 → 机器人管理 → 页面顶部「订单推送渠道」

**4 种可选方案**：

| 选项 | 含义 | 说明 |
|---|---|---|
| 不推送 | 关闭订单通知 | 订单到账时不会主动推送，需进入后台手动确认 |
| 仅邮件 | 只发邮件 | 需先在「📧 邮件推送」里配置好收件邮箱 |
| 仅 TG | 只推 TG | 需先在「机器人管理」里绑定 TG 或配置自建机器人 |
| 邮件 + TG | 双保险 | 两个渠道都会推送，建议无人值守场景使用 |

**⚠️ 标准商户组（gid=4）强制自建**：
- 选「仅邮件」或「邮件 + TG」→ **必须**在「邮件推送」里填自己的 SMTP 服务器（主机/账号/密码/端口），平台不会用默认邮箱代发
- 选「仅 TG」或「邮件 + TG」→ **必须**在「机器人管理」里配置自己的 Bot Token（`use_own_bot=1`），平台主机器人不会代发
- 只配了「收件邮箱」但没配 SMTP，或只填了 Chat ID 但没配 Bot Token，保存时会提示错误，无法生效

**平台管理方（gid=0）例外**：可以使用平台默认 SMTP 和默认机器人兜底推送。

## 十、邮件营销与追踪系统

### 📌 功能定位

商户向自己的客户群发营销邮件（促销、通知、召回等），并追踪每封邮件的打开 / 点击 / 落地页 / 转化数据。

- 发件人 = 你自己的邮箱（用你的 SMTP）

- 追踪 = 内置 1×1 像素 + 链接重写 + 落地页 SDK

- 数据保留 7 天，需及时导出 CSV

### 10.1 前置准备 - 配置发件邮箱

必须先做：没配 SMTP 无法发送。

- 后台 → 推送 → 邮件推送（/user/mail_push.php）

- 填写 SMTP 服务器、端口、用户名、密码（授权码）

常用配置参考：

| 邮箱 | SMTP 服务器 | 端口 | 加密

| Gmail | smtp.gmail.com | 465 / 587 | SSL / TLS

| QQ 邮箱 | smtp.qq.com | 465 | SSL（授权码）

| 163 邮箱 | smtp.163.com | 465 | SSL（授权码）

| iCloud | smtp.mail.me.com | 587 | TLS（应用专用密码）

| Outlook | smtp.office365.com | 587 | TLS

注意：多数邮箱用 授权码（不是登录密码），要在邮箱设置里生成。

### 10.2 功能入口

| 页面 | 路径 | 作用

| 📧 邮件推送 | /user/mail_push.php | 配置 SMTP 发件邮箱

| 📣 邮件营销 | /user/mail_marketing/index.php | 活动列表

| 📄 邮件模板 | /user/mail_marketing/templates.php | 模板管理

### 10.3 创建邮件活动

后台 → 邮件营销 → 点「➕ 新建活动」

#### 填写内容

| 字段 | 说明

| 活动名 * | 仅自己可见，方便管理（如「双十一促销」）

| 邮件主题 * | 收件人看到的标题

| 发件人显示名 | 选填（如「XX 商城」），默认显示你的邮箱

| 邮件正文 * | HTML 编辑器（支持所有 HTML 标签）

| 收件人 * | 手动输入 / 从订单买家邮箱勾选

#### 正文来源 3 种方式

- 直接编辑：在文本框里写 HTML

- 从模板导入：选已有模板一键填入

- 导入本地 HTML：点「导入 HTML」选本地 .html 文件（UTF-8）

#### 收件人来源 2 种方式

- 手动粘贴：每行一个，或用逗号/分号/空格分隔

系统自动去重 + 格式校验，无效邮箱会红字提示

- 从订单拉取：点「加载历史买家邮箱」→ 勾选（支持全选）

取自己名下所有已支付订单的买家邮箱

邮箱验证规则（保存时会强制校验）：

- 格式必须合法（正则验证）

- 域名不能是测试/保留域名（example.com、test.com、mailinator 等）

- 域名必须有 MX 或 A 记录（checkdnsrr 检查）

- 不符合的会显示具体原因，需修正后重新提交

### 10.4 发送控制

创建活动后自动跳到详情页（view.php?id=xxx），在「发送控制」面板里操作。

#### 发送策略 5 种

| 模式 | 批量 | 间隔 | 适用场景

| ⚡ 极速 | 20 封/批 | 0.3 秒/封 | Gmail/QQ 等宽松邮箱

| ✅ 标准（推荐） | 10 封/批 | 1 秒/封 | 大多数场景

### 10.8 落地页追踪 SDK（高级）

用途：把追踪装到你自己的落地页上，统计访问和转化。

#### 接入步骤

- 后台 → 邮件营销 → 「追踪接入」（track_sdk.php）页面有完整说明

- 把 SDK 脚本加到落地页 <head> 里：

<script src="https://pay.yunzexinda.com/mail_track/track/sdk.js"></script>

- 邮件里的链接会自动加 mt_rid=xxx 参数，SDK 检测到就自动追踪

#### 上报转化事件

在落地页支付成功/下单成功时调：

mtTrack.event('purchase', {amount: 199, order: 'ORD123'});
后台就能在「追踪明细 → 仅转化」看到，显示金额和订单号。

原理：

- 邮件里的 <a href> 全部被重写成 click.php?t=token&url=base64

- 用户点击 → click.php 记录事件 → 302 跳到真实 URL 并加 ?mt_rid=token

- 落地页 SDK 读 mt_rid，自动上报 landing 事件

- 页面里调 mtTrack.event() 上报自定义转化

### 10.9 常见问题

#### Q1：点「开始发送」没反应？

- 检查 SMTP 是否配好（mail_push.php）

- 检查有没有未发送的收件人（顶部「未发送」数字）

- F12 Console 看是否有 JS 错误

#### Q2：发送失败率高？

- 看收件人列表的失败原因（鼠标悬停在红色「失败」标签）

- 常见原因：邮箱不存在 / SMTP 限流 / 被当垃圾邮件

- 换「慢速稳发」模式再试

#### Q3：打开率是 0？

- 很多邮箱默认屏蔽远程图片（追踪像素就是图片）

- 用户必须「显示图片」才能记录打开

- 所以真实打开率通常比统计值高

#### Q4：能发多少封？

- 系统限制：单批最多 100，每封间隔 ≥ 0.3 秒

- 实际上限取决于你的 SMTP 服务商（Gmail 免费版 500/天，企业版 2000/天）

- QQ 邮箱每天 50 封左右

#### Q5：收件人会看到追踪吗？

- 打开追踪：看不见（1×1 透明像素）

- 链接追踪：看不见跳转（302 秒跳）

- 落地页 URL 会多一个 ?mt_rid=xxx 参数（无感）

## 十一、常见问题

### Q1：下单后客户看不到收款码？

- 检查商户有没有启用的收款码（status=1）

- 检查收款码限额是否覆盖订单金额

- 检查服务期是否有效

### Q2：订单已经付款但系统没完成？

- APK 是否在线（查看手机 APP 状态）

- 金额和时间是否在 10 分钟内匹配

- 看码 owner 余额是否不足

### Q3：邮件没收到？

- 检查推送资料是否通过审批

- SMTP 配置是否正确

- 看垃圾邮件箱

### Q4：下级收不到推送？

- 下级推送资料是否已填 + 上级审批通过

- 订单 pushUid 是否是下级 uid
